## LangChain 메모리

정리 문서: [대화 메모리 정리](../AI/langchain_langsmith.md#대화-메모리)

LLM은 기본적으로 이전 요청을 기억하지 않는다. 이전 메시지를 다음 요청에 함께 전달해야 대화가 이어진다.

`InMemoryChatMessageHistory`를 세션 ID별로 사용하면 여러 사용자의 대화를 나눠 관리할 수 있다. 다만 프로세스가 종료되면 기록이 사라진다.

대화가 길어지면 전체 기록을 그대로 보내지 않고 트리밍, 요약, 검색으로 전달할 메시지를 줄인다. `trim_messages()`는 원본 기록은 유지하면서 모델에 보낼 메시지만 선택한다.

## Structured Output

정리 문서: [Structured Output 정리](../AI/langchain_langsmith.md#structured-output과-output-parser)

LLM의 문자열 응답을 필요한 Python 자료형으로 변환한다.

- `StrOutputParser`: 문자열
- `JsonOutputParser`: dict 또는 list
- `PydanticOutputParser`: Pydantic 객체와 schema 검증
- `with_structured_output()`: 모델의 네이티브 구조화 출력

`Literal`로 허용값을 제한하고 `Field`로 숫자 범위나 문자열 길이를 설정할 수 있다. JSON 형식, schema, 업무 규칙, 서비스 정책은 각각 별도로 검증해야 한다.

## Tool과 Agent

정리 문서: [Tool과 Agent 정리](../AI/langchain_langsmith.md#tool과-agent)

Tool은 LLM이 외부 함수나 API를 사용할 수 있게 해 주는 기능이다.

```text
질문 → 모델의 tool_call → 애플리케이션에서 함수 실행
→ ToolMessage 전달 → 모델의 최종 답변
```

`@tool`로 일반 함수를 Tool로 만들 수 있다. 함수 이름, docstring, 타입 힌트가 모델이 Tool을 선택하고 인자를 만드는 기준이 된다.

`bind_tools()`는 Tool을 모델에 알려줄 뿐 실행하지 않는다. `AIMessage.tool_calls`를 확인해 등록된 함수만 실행하고, 결과를 `ToolMessage`로 다시 전달한다. 여러 Tool 호출과 반복을 처리할 때는 최대 반복 횟수를 둬 무한 실행을 막는다.

## RAG

정리 문서: [RAG 기초 정리](../AI/rag_basic.md#rag란)

RAG는 관련 문서를 검색한 뒤 그 내용을 LLM에 넣어 답변을 만드는 방식이다. 모델을 재학습하지 않고 최신 문서나 사내 자료를 활용할 수 있다.

```text
문서 → Loader → Chunk 분할 → Embedding → 저장
질문 → 질문 Embedding → 유사 문서 검색 → LLM → 답변
```

### 문서 처리

- `TextLoader`: 텍스트 파일
- `PyPDFLoader`: PDF를 페이지별 `Document`로 변환
- `RecursiveCharacterTextSplitter`: 문단·줄·단어 경계를 고려해 청크 분할
- `chunk_overlap`: 청크 사이의 문맥 단절을 줄임

`Document`는 `page_content`와 `metadata`로 구성된다. metadata에 파일 경로와 페이지를 보관하면 답변 출처를 추적할 수 있다.

### 임베딩과 검색

임베딩은 텍스트를 벡터로 바꾸는 과정이다. 질문과 문서를 같은 임베딩 모델로 변환하고 코사인 유사도 등으로 가까운 문서를 찾는다.

검색 결과가 틀리면 최종 답변도 틀릴 수 있으므로 RAG에서는 청킹 크기, 임베딩 모델, 검색 결과의 관련성을 함께 확인해야 한다.
