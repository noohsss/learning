## 기본 그래프

`StateGraph`로 간단한 챗봇 그래프를 구성하는 기본 형태다.

```python
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

class State(TypedDict):
    question: str
    answer: str

def chatbot(state: State):
    response = llm.invoke(state["question"])
    return {"answer": response.content}

builder = StateGraph(State)
builder.add_node("chatbot", chatbot)
builder.add_edge(START, "chatbot")
builder.add_edge("chatbot", END)

graph = builder.compile()
result = graph.invoke({"question": "LangGraph가 뭐야?"})
```

구성 순서는 `State 정의 → Node 등록 → Edge 연결 → compile → invoke`다. 노드는 전체 상태가 아니라 변경할 값만 반환하고, 반환된 값은 다음 단계의 State에 반영된다.

## 여러 Node 연결

작업을 `plan`과 `write`로 나누어 순서대로 연결할 수 있다.

```python
def make_plan(state):
    return {"plan": "질문 분석 후 답변 작성"}

def write_answer(state):
    return {"answer": f"계획: {state['plan']}"}

builder.add_node("plan", make_plan)
builder.add_node("write", write_answer)
builder.add_edge(START, "plan")
builder.add_edge("plan", "write")
builder.add_edge("write", END)
```

```text
START → plan → write → END
```

## 조건부 분기

언어를 판별한 결과에 따라 한국어 답변 노드와 영어 답변 노드로 나눌 수 있다.

```python
def route_by_language(state):
    return state["language"]

graph_builder.add_conditional_edges(
    "detect_language",
    route_by_language,
    {
        "ko": "answer_ko",
        "en": "answer_en",
    },
)
```

감정 분석에서도 같은 방식으로 `analyze` 결과가 `positive`인지 `negative`인지에 따라 응답 노드를 선택할 수 있다.

```text
analyze
  ├─ positive → positive_response
  └─ negative → negative_response
```

## 반복과 재시도

카운트가 5가 될 때까지 같은 Node를 반복 실행하는 그래프를 구성할 수 있다.

```python
class CountState(TypedDict):
    count: int

def increment(state: CountState):
    return {"count": state["count"] + 1}

def route_by_count(state: CountState):
    if state["count"] >= 5:
        return "end"
    return "continue"

builder.add_node("increment", increment)
builder.add_edge(START, "increment")
builder.add_conditional_edges(
    "increment",
    route_by_count,
    {"continue": "increment", "end": END},
)
```

```text
count < 5  → increment로 돌아감
count >= 5 → END
```

숫자 맞히기는 `guess → check` 흐름으로 만들고, 틀리면 `guess`로 돌아가도록 구성할 수 있다. 반복을 사용할 때 종료 조건이 없으면 무한 루프가 생길 수 있다.

## 작성·검토·재작성 흐름

글을 작성한 뒤 검토 결과에 따라 종료하거나 다시 작성하는 Workflow 구조다.

```text
write → review
          ├─ pass → END
          └─ fail → write
```

검토 결과를 `Literal["pass", "fail"]` 또는 Pydantic 모델로 제한하면 라우팅 값이 정해진 형식에서 벗어나지 않도록 관리할 수 있다.

## State와 Reducer

기본 State 필드는 새 값으로 덮어써지지만, 메시지와 로그처럼 여러 Node의 결과를 모아야 하는 값은 reducer로 누적할 수 있다.

```python
import operator
from typing import Annotated
from langgraph.graph.message import add_messages

class ReducerState(TypedDict):
    name: str
    messages: Annotated[list, add_messages]
    logs: Annotated[list, operator.add]
```

- `name`: 새 값으로 교체
- `messages`: 메시지 누적 및 관리
- `logs`: 리스트 이어 붙이기

## 실행 결과 확인

```python
result = graph.invoke({"question": "질문"})

for update in graph.stream({"question": "질문"}):
    print(update)

for state in graph.stream(
    {"question": "질문"},
    stream_mode="values",
):
    print(state)
```

- `invoke()`: 최종 State 확인
- `graph.stream()`: Node별 업데이트 확인
- `stream_mode="values"`: 각 단계의 전체 State 확인
- `llm.stream()`: LLM 토큰 단위 출력

## 실습 1. 감정 분석 라우터

사용자의 문장을 받아 감정을 분석하고, 긍정이면 긍정 응답, 부정이면 위로 응답을 생성하는 그래프를 만들어보자.

```text
START → analyze → 긍정? → respond_positive → END
                   부정? → respond_negative → END
```

**테스트 입력**:
```python
sentiment_graph.invoke({"text": "오늘 승진했어! 너무 기뻐!"})
sentiment_graph.invoke({"text": "프로젝트가 엎어졌어... 힘들다"})
```

```python
class EmotionState(TypedDict):
    text: str
    emotion: str
    answer: str

def analyze(state: EmotionState):
    text = state["text"]
    result = llm.invoke(f"다음 <text>의 감정이 긍정이면 '긍정', 부정이면 '부정'이라고 판단해서 답해줘 <text>{text}</text>")
    return {"emotion": result.text}

def respond_positive(state: EmotionState):
    text = state["text"]
    result = llm.invoke(f"다음 <text>을 보고 긍정적인 답변을 30자 이내로 해줘. <text>{text}</text>")
    return {"answer": result.text}

def respond_negative(state: EmotionState):
    text = state["text"]
    result = llm.invoke(f"다음 <text>을 보고 위로하는 답변을 30자 이내로 해줘. <text>{text}</text>")
    return {"answer": result.text}

def route(state: EmotionState):
    if "긍정" in state["emotion"]:
        return "positive"
    else:
        return "negative"

graph_builder = StateGraph(EmotionState)

graph_builder.add_node("analyze", analyze)
graph_builder.add_node("respond_positive", respond_positive)
graph_builder.add_node("respond_negative", respond_negative)
graph_builder.add_edge(START, "analyze")

builder.add_conditional_edges(
    "analyze",
    route,
    {
        "positive": "respond_positive",
        "negative": "respond_negative"
    },
)

graph_builder.add_edge("respond_positive", END)
graph_builder.add_edge("respond_negative", END)

graph = graph_builder.compile()

display(Image(graph.get_graph().draw_mermaid_png()))
```

## 실습 2. 숫자 맞히기

LLM이 1~100 사이의 숫자를 추측하고, 정답이 아니면 범위를 좁혀 다시 시도하는 그래프를 만들어보자.

```text
START → guess → check → 정답? → END
                  ↑      오답? → guess로 돌아감
```

`check` 노드는 추측값이 정답보다 작으면 `low`를 높이고, 크면 `high`를 낮춘다. 예를 들어 정답이 37일 때 50을 추측하면 다음 추측 범위는 1~49가 된다.

**테스트 입력**:
```python
guess_graph.stream({"target": 37})
```

```python
class NumberState(TypedDict):
    target: int
    low: int
    high: int
    number: int

def guess(state: NumberState):
    low = state["low"]
    high = state["high"]
    result = llm.invoke(f"{low} ~ {high} 사이의 **정수인 숫자만** 하나 말해줘.")
    return {"number": int(result.text)}

def check(state: NumberState):
    target = state["target"]
    number = state["number"]

    if number < target:
        return {
                "low": number + 1, 
                }
    return {
            "high": number - 1, 
            }

def route(state: NumberState):
    target = state["target"]
    number = state["number"]

    if number == target:
        return "end"
    return "continue"

graph_builder = StateGraph(NumberState)
graph_builder.add_node("guess", guess)
graph_builder.add_node("check", check)

graph_builder.add_edge(START, "guess")
graph_builder.add_edge("guess", "check")
graph_builder.add_conditional_edges(
    "check",
    route,
    {
        "continue": "guess",
        "end": END
    }
)

graph = graph_builder.compile()
display(Image(graph.get_graph().draw_mermaid_png()))

for event in graph.stream(
    {
        "target": 37,
        "low": 1,
        "high": 100,
    }):
    for node_name, value in event.items():
        print(f"[{node_name}] {value}")
        print()

```

## 실습 3. 작성·검토·재작성

주제를 받아 짧은 글을 작성하고, 검토 후 품질이 부족하면 피드백을 반영해 다시 작성하는 그래프를 만들어보자.

```text
START → write → review → 통과? → END
                         미흡? → write로 돌아감
```

**테스트 입력**:
```python
writing_graph.stream({"topic": "AI가 교육에 미치는 영향"})
```

```python
from typing import Literal

from pydantic import BaseModel


class WirteState(TypedDict):
    topic: str
    sentence: str
    feedback: str
    result: Literal["pass", "fail"]


class ReviewResult(BaseModel):
    result: Literal["pass", "fail"]
    feedback: str


llm_with_review_result = llm.with_structured_output(ReviewResult)


def write(state: WirteState):
    topic = state["topic"]
    feedback = state.get("feedback", "")
    sentence = state.get("sentence", "")

    if feedback != "" and sentence != "":
        response = llm.invoke(f"""
        주제: {topic}
        피드백: {feedback}
        이전 작성 글: {sentence}

        이전 작성 글에 피드백을 반영해서 주제에 맞는 간단한 글을 작성해줘.
        """)
    else:
        response = llm.invoke(f"다음 {topic}에 대한 50자 이내에 글을 작성해줘.")

    return {"sentence": response.text}


def review(state: WirteState):
    sentence = state["sentence"]
    topic = state["topic"]

    response = llm_with_review_result.invoke(f"""
        다음 <sentence>은 <topic>을 주제로 한 글이야.
        - result에는 전문적이고 자세한 글이면 "pass"를 아니면 "fail"을 넣어줘.
        - feedback에는 그렇게 생각한 이유를 명시해줘.

        <sentence>{sentence}</sentence>
        <topic>{topic}</topic>
        """)

    return {"result": response.result, "feedback": response.feedback}


def route(state: WirteState):
    return state["result"]


graph_builder = StateGraph(WirteState)
graph_builder.add_node("write", write)
graph_builder.add_node("review", review)

graph_builder.add_edge(START, "write")
graph_builder.add_edge("write", "review")

graph_builder.add_conditional_edges("review", route, {"fail": "write", "pass": END})

graph = graph_builder.compile()
display(Image(graph.get_graph().draw_mermaid_png()))

for event in graph.stream({"topic": "AI가 교육에 미치는 영향"}):
    for node_name, value in event.items():
        print(f"[{node_name}] {value}")
        print()
```

클래스로 그래프 구성과 실행에 필요한 LLM을 묶는 방식도 작성했다.

```python
class WriteState(TypedDict):
    topic: str
    sentence: str
    feedback: str
    result: Literal["pass", "fail"]


class ReviewResult(BaseModel):
    result: Literal["pass", "fail"]
    feedback: str

class WriteGraph:
    def __init__(self, llm, review_llm):
        self.llm = llm
        self.review_llm = review_llm
        self.graph = self.build_graph()


    def write(self, state: WriteState):
        topic = state["topic"]
        feedback = state.get("feedback", "")
        sentence = state.get("sentence", "")

        if feedback != "" and sentence != "":
            response = self.llm.invoke(f"""
            주제: {topic}
            피드백: {feedback}
            이전 작성 글: {sentence}

            이전 작성 글에 피드백을 반영해서 주제에 맞는 간단한 글을 작성해줘.
            """)
        else:
            response = self.llm.invoke(f"다음 {topic}에 대한 50자 이내에 글을 작성해줘.")

        return {"sentence": response.text}

    
    def review(self, state: WriteState):
        sentence = state["sentence"]
        topic = state["topic"]

        response = self.review_llm.invoke(f"""
            다음 <sentence>은 <topic>을 주제로 한 글이야.
            - result에는 전문적이고 자세한 글이면 "pass"를 아니면 "fail"을 넣어줘.
            - feedback에는 그렇게 생각한 이유를 명시해줘.

            <sentence>{sentence}</sentence>
            <topic>{topic}</topic>
            """)

        return {"result": response.result, "feedback": response.feedback}
    

    def route(self, state: WriteState):
        return state["result"]

    def build_graph(self):
        graph_builder = StateGraph(WriteState)

        graph_builder.add_node("write", self.write)
        graph_builder.add_node("review", self.review)

        graph_builder.add_edge(START, "write")
        graph_builder.add_edge("write", "review")

        graph_builder.add_conditional_edges(
            "review",
            self.route,
            {
                "fail": "write",
                "pass": END
            }
        )

        graph = graph_builder.compile()
        return graph
```

## 핵심 정리

- `StateGraph`는 State 기반의 실행 흐름을 구성한다.
- 조건부 Edge로 감정·언어에 따른 분기를 만들 수 있다.
- 순환 Edge로 숫자 맞히기와 재시도 흐름을 구성할 수 있다.
- `write → review → rewrite`는 대표적인 Workflow 구조다.
- Reducer는 메시지와 로그를 누적할 때 사용한다.
- `invoke()`와 그래프 `stream()`은 결과를 확인하는 방식이 다르다.

자세한 개념, Node 분리 기준, Chain·Workflow·Agent 비교는 [LangGraph 기초 상세 정리](../../AI/langgraph_basic.md#langgraph란)에서 확인한다.
