## RAG Agent

Retriever를 Tool로 등록하면 Agent가 검색 필요 여부를 판단하는 대화형 RAG를 구성할 수 있다. Checkpointer를 연결하면 이전 검색 결과와 대화 맥락을 후속 질문에 사용할 수 있다.

~~~text
질문 → 검색 필요 여부 판단
        ├─ 필요 → Retriever Tool → 답변
        └─ 불필요 → 바로 답변
~~~

### 실습 문제: SPRi AI Brief 검색 Agent

SPRi AI Brief 9월호, 10월호, 11월호를 활용해 AI 산업 동향을 검색하는 대화형 RAG Agent를 구성한다.

~~~python
        pages = PyPDFLoader(path).load()
        # 검색 필터에 사용할 메타데이터를 페이지마다 저장한다.
        for page in pages:

        # 페이지를 청크로 나누고 각 청크에 고유 ID를 부여한다.
        chunks = splitter.split_documents(pages)
        for chunk_index, chunk in enumerate(chunks):
            chunk.metadata["chunk_id"] = f"{path.stem}:{chunk_index}"
        documents.extend(chunks)

    # 같은 컬렉션이 있으면 삭제하여 문서가 중복 저장되지 않게 한다.
    client = chromadb.PersistentClient(path=PERSIST_DIR)
    existing_names = [collection.name for collection in client.list_collections()]
    if COLLECTION_NAME in existing_names:
        client.delete_collection(COLLECTION_NAME)

    # 모든 청크를 임베딩하여 Chroma에 저장한다.
    vectorstore = Chroma.from_documents(
        documents=documents,
        embedding=embeddings,
        collection_name=COLLECTION_NAME,
        client=client,
    )
    print(f"PDF {len(pdf_paths)}개, 청크 {len(documents)}개")
    print("월호:", [f"{path.name}" for path in pdf_paths])
    has_documents = True
    print(f"규정 청크 {len(documents)}개를 새로 저장했습니다.")
~~~

## Router

Router는 요청을 분류해 전문 처리 노드로 전달한다.

- Deterministic Routing: 확정적인 규칙과 키워드 사용
- LLM Routing: 맥락 해석이 필요한 의도 분류
- Semantic Routing: 임베딩 유사도 기반 분류
- Hybrid Routing: 규칙, Semantic, LLM과 fallback 조합

명확한 요청은 규칙으로 처리하고 애매한 요청만 LLM으로 보내면 비용과 지연을 줄일 수 있다. 목적지가 많으면 Domain Router와 하위 Router를 나누는 Hierarchical Routing을 고려할 수 있다.

평가 기준은 routing accuracy, fallback rate, unsafe routing rate, latency, token cost다.

## Guardrails

Guardrail은 Agent가 허용 범위 안에서만 판단하고 행동하도록 제한하는 장치다.

~~~text
User → Input Guardrail → Agent/LLM → Tool Guardrail → Tools/API
                                      ↓
                              Output Guardrail → User
~~~

Input Guardrail은 빈 입력, 길이, 유해 요청과 프롬프트 인젝션을 검사한다. Output Guardrail은 민감정보, 금지 콘텐츠, 응답 형식을 검사한다. Tool Guardrail은 권한과 인자를 확인하고, Runtime Guardrail은 호출 횟수·시간·비용을 제한한다.

## Reflection과 Evaluator-Optimizer

Reflection은 생성 결과를 다시 검토하고 피드백을 반영해 재생성하는 패턴이다. Evaluator-Optimizer는 평가 결과를 점수와 근거로 구조화하고, 합격 기준에 미달한 항목을 개선한다.

### 실습: 제품 리뷰 요약

~~~python
REVIEW = """\
[무선 블루투스 이어폰 - StarBuds Pro 리뷰]

저는 이 이어폰을 출퇴근용으로 3개월째 사용하고 있습니다. 먼저 음질은 가격대비 정말 \
훌륭합니다. 저음이 풍부하고 고음도 깨끗하게 들립니다. 특히 팟캐스트를 들을 때 목소리가 \
또렷하게 들려서 좋습니다.

노이즈 캔슬링은 지하철에서 테스트해봤는데, 완전 차단까지는 아니지만 주변 소음을 \
70~80% 정도 줄여줍니다. 출퇴근 시 음악 감상에는 충분합니다. 다만 바람이 부는 야외에서는 \
노캔 성능이 많이 떨어집니다.

배터리는 공식 스펙이 7시간인데 실사용 5시간 반 정도 갑니다. 노캔 켜면 4시간 정도로 \
줄어듭니다. 케이스 충전 포함하면 총 20시간 정도 사용 가능합니다.

착용감은 제 귀에는 잘 맞는데, 귀가 작은 아내는 30분만 끼면 아프다고 합니다. 이어팁이 \
3종류 들어있긴 한데 가장 작은 것도 좀 큰 편입니다.

통화 품질은 솔직히 별로입니다. 상대방이 제 목소리가 멀리서 들린다고 합니다. \
조용한 실내에서는 괜찮은데 밖에서는 통화하기 어렵습니다.

앱 연동은 EQ 조절이 가능하고 노캔 강도도 조절할 수 있어서 편리합니다. \
다만 앱이 가끔 블루투스 연결이 끊기는 버그가 있습니다.

총평: 7만원대에 이 정도면 가성비 좋습니다. 통화보다 음악 감상 위주로 쓸 분께 추천합니다. \
통화를 많이 하시는 분은 다른 제품을 알아보시는 게 좋을 것 같습니다.
~~~

~~~python
load_dotenv()

TASK_MODEL_NAME = "gemini-2.5-flash-lite"
REVIEW_MODEL_NAME = "gemini-3.6-flash"

gen_llm = ChatGoogleGenerativeAI(model=TASK_MODEL_NAME)
review_llm = ChatGoogleGenerativeAI(model=REVIEW_MODEL_NAME)
~~~

~~~python
# 완성한 그래프를 review_reflection_graph에 저장하세요.
class ReviewReflectionState(TypedDict):
    messages: Annotated[list, add_messages]
    iteration: int


MAX_ITERATIONS = 3


def generate_summary(state: ReviewReflectionState):
    system = SystemMessage(content="""
너는 제품 리뷰 요약 전문가다.
사용자가 제공한 리뷰를 한 문단(3~5문장)으로 요약하라.

작성 원칙:
- 장점과 단점을 균형 있게 포함한다.
- 어떤 사용자에게 추천하거나 추천하지 않는지 명확히 포함한다.
- 원문에 없는 정보, 성능 수치, 추측은 추가하지 않는다.
- 이전 피드백이 있으면 반영하되, 피드백이나 수정 과정은 언급하지 않는다.

출력 형식:
- 요약 문단 본문만 출력한다.
- 제목, 불릿, 해설, 머리말은 출력하지 않는다.
""")

    response = gen_llm.invoke([system, *state["messages"]])

    return {
        "messages": [AIMessage(content=response.text)],
        "iteration": state.get("iteration", 0) + 1,
    }


def reflect_summary(state: ReviewReflectionState):
    system = SystemMessage(content="""
너는 제품 리뷰 요약 편집자다.
원문 리뷰와 최신 요약을 비교하여, 다음 수정에 바로 반영할 수 있는 피드백만 작성하라.
요약을 직접 다시 작성하지 않는다.

검토 기준:
- 정확히 3~5문장인 한 문단인가?
- 원문의 핵심 장점이 구체적으로 포함되었는가?
- 원문의 핵심 단점이 구체적으로 포함되었는가?
- 추천 대상과 비추천 대상이 원문의 근거에 맞게 포함되었는가?
- 불필요한 반복이나 원문에 없는 추측이 없는가?

출력 형식:
- 개선이 필요한 항목만 불릿 목록으로 작성한다.
- 각 항목에 문제점과 수정 방향을 함께 작성한다.
- 칭찬, 점수, 총평은 출력하지 않는다.
""")

    original_review = state["messages"][0]
    latest_summary = state["messages"][-1]

    response = review_llm.invoke([
        system,
        HumanMessage(content=(
            f"<review>\n{original_review}\n</review>\n\n"
            f"<summary>\n{latest_summary}\n</summary>"
        )),
    ])

    return {"messages": [HumanMessage(content=response.text)]}


def route(state: ReviewReflectionState):
    return "end" if state["iteration"] >= MAX_ITERATIONS else "continue"


builder = StateGraph(ReviewReflectionState)

builder.add_node("generate", generate_summary)
builder.add_node("reflect", reflect_summary)

builder.add_edge(START, "generate")
builder.add_conditional_edges(
    "generate",
    route,
    {"continue": "reflect", "end": END},
)
builder.add_edge("reflect", "generate")

review_reflection_graph = builder.compile()


result = review_reflection_graph.invoke(
    {"messages": [HumanMessage(content=REVIEW)], "iteration": 0}
)

print(f"총 반복 횟수: {result['iteration']}")
print(f"총 메시지 수: {len(result['messages'])}")
print("\n" + "=" * 60)

for msg in result["messages"]:
    print(f"\n[{msg.type}]")
    print(msg.text[:500])
    print("-" * 40)
~~~

~~~python
# 완성한 그래프를 review_eval_opt_graph에 저장하세요.
# 최종 요약은 summary, 평가 결과는 evaluation에 저장하세요.
PASS_THRESHOLD = 8

class Evaluation(BaseModel):
    completeness: int = Field(ge=1, le=10, description="장점·단점·가격 정보 반영 점수")
    accuracy: int = Field(ge=1, le=10, description="원문 사실 일치 및 환각 없음 점수")
    conciseness: int = Field(ge=1, le=10, description="3~5문장, 간결성 점수")
    recommendation: int = Field(ge=1, le=10, description="추천·비추천 대상 포함 점수")
    feedback: str = Field(description="다음 수정에 반영할 구체적인 개선 사항")


class ReviewEvalOptState(TypedDict):
    summary: str
    feedback: str
    evaluation: Evaluation | None


def generate_summary(state: ReviewEvalOptState):
    system = SystemMessage(content="""
너는 제품 리뷰 요약 전문가다.
사용자가 제공한 리뷰를 한 문단(3~5문장)으로 요약하라.

작성 원칙:
- 장점과 단점을 균형 있게 포함한다.
- 어떤 사용자에게 추천하거나 추천하지 않는지 명확히 포함한다.
- 원문에 없는 정보, 성능 수치, 추측은 추가하지 않는다.
- 이전 피드백이 있으면 반영하되, 피드백이나 수정 과정은 언급하지 않는다.

출력 형식:
- 요약 문단 본문만 출력한다.
- 제목, 불릿, 해설, 머리말은 출력하지 않는다.
""")

    feedback = state.get("feedback", "")
    prompt = f"<review>\n{REVIEW}\n</review>"

    if feedback:
        prompt += f"\n\n<feedback>\n{feedback}\n</feedback>"

    response = gen_llm.invoke([system, HumanMessage(content=prompt)])

    return {
        "summary": response.text,
    }


def evaluate_summary(state: ReviewEvalOptState):
    evaluator = review_llm.with_structured_output(Evaluation)

    system = SystemMessage(content="""
너는 제품 리뷰 요약 평가자다.
원문 리뷰와 요약을 비교하여 루브릭별로 1~10점을 평가한다.

평가 기준:
- completeness: 핵심 장점과 단점이 각각 1개 이상 포함되고 가격 정보가 반영되면 높은 점수
- accuracy: 가격, 배터리 시간, 성능 등 원문 사실이 정확하고 원문 밖 정보가 없으면 높은 점수
- conciseness: 불필요한 반복 없이 정확히 3~5문장 한 문단이면 높은 점수
- recommendation: 적합한 사용자와 부적합한 사용자를 원문의 근거와 함께 모두 언급하면 높은 점수

feedback에는 8점 미만 항목을 중심으로 구체적인 수정 방향을 작성한다.
""")

    evaluation = evaluator.invoke([
        system,
        HumanMessage(content=(
            f"<review>\n{REVIEW}\n</review>\n\n"
            f"<summary>\n{state['summary']}\n</summary>"
        )),
    ])

    return {
        "evaluation": evaluation,
        "feedback": evaluation.feedback,
    }


def route(state: ReviewEvalOptState):
    evaluation = state["evaluation"]

    passed = all([
        evaluation.completeness >= PASS_THRESHOLD,
        evaluation.accuracy >= PASS_THRESHOLD,
        evaluation.conciseness >= PASS_THRESHOLD,
        evaluation.recommendation >= PASS_THRESHOLD,
    ])

    if passed:
        return "end"
    return "optimize"


builder = StateGraph(ReviewEvalOptState)

builder.add_node("generate", generate_summary)
builder.add_node("evaluate", evaluate_summary)

builder.add_edge(START, "generate")
builder.add_edge("generate", "evaluate")
builder.add_conditional_edges(
    "evaluate",
    route,
    {"optimize": "generate", "end": END},
)

review_eval_opt_graph = builder.compile()


result = review_eval_opt_graph.invoke({
    "summary": "",
    "feedback": "",
    "evaluation": None,
})

print("최종 요약:")
print(result["summary"])
print("\n평가 결과:")
print(result["evaluation"])
~~~
