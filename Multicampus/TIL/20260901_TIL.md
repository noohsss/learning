# 20260901

## 프롬프트 엔지니어링

프롬프트를 잘 작성해 원하는 답변을 얻는 방법.

### 기본 구성

- **지시**: 모델이 할 일
- **문맥**: 상황과 배경
- **입력**: 처리할 데이터
- **출력 형식**: 답변 모양

역할, 예시, 제약 조건, 구조화 태그를 추가하면 결과를 조절하기 쉽다.

### 주요 기법

- **Zero-shot**: 예시 없이 바로 요청
- **Few-shot**: 입력과 출력 예시를 함께 제공
- **역할 지정**: 직함보다 상황, 목표, 판단 기준까지 적는 편이 좋음
- **출력 형식 지정**: 표, JSON, 문장 수 등을 명시
- **구조화 태그**: `<context>`, `<instruction>` 등으로 지시와 데이터를 구분
- 복잡한 문제는 단계로 나누고 계산식, 인용, 테스트 결과처럼 확인 가능한 근거를 요청

프롬프트는 답변 방향을 잡을 뿐, 내용의 사실성까지 보장하지 않는다.

### 프롬프트를 나누는 기준

바뀌지 않는 규칙은 system, 매번 달라지는 질문이나 데이터는 human에 둔다.

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", "너는 {role}이다. 한국어로 답해."),
    ("human", "다음 질문에 답해: {question}"),
])

prompt_value = prompt.invoke({
    "role": "Python 튜터",
    "question": "리스트와 튜플의 차이는?",
})
```

`PromptTemplate`은 단일 문자열 프롬프트, `ChatPromptTemplate`은 system·human·ai 역할을 나눌 때 사용한다.

### 프롬프트 체이닝

복잡한 작업을 여러 단계로 나눠 앞 단계의 결과를 다음 단계에 전달한다.

```text
주제 입력 → 설명 생성 → 결과 정리 → 최종 출력
```

한 번에 모든 일을 시키는 것보다 각 단계의 입력과 출력이 분명해진다.

### 구조화 출력

JSON 모양만 요청하는 것보다 Pydantic 같은 스키마를 사용하는 편이 안전하다.
필드와 자료형은 확인할 수 있지만, 모델이 만든 내용의 사실 여부까지 보장하지는 않는다.

## LangChain 기본

정리 문서: [LangChain 정리](../AI/langchain_langsmith.md#langchain)

LangChain은 LLM, 프롬프트, 출력 파서, 메모리, Tool 등을 연결하는 프레임워크다.

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_messages([
    ("system", "너는 Python 튜터야."),
    ("human", "{question}"),
])

chain = prompt | llm | StrOutputParser()
result = chain.invoke({"question": "decorator가 뭐야?"})
```

- `ChatGoogleGenerativeAI`: Gemini용 ChatModel
- `SystemMessage`: 역할과 공통 규칙
- `HumanMessage`: 사용자 입력
- `AIMessage`: 모델 응답
- `StrOutputParser`: `AIMessage`에서 문자열만 추출
- `invoke()`: Runnable 실행

### LCEL과 Runnable

`|`로 구성 요소를 연결한다. 모든 구성 요소는 `Runnable` 인터페이스를 사용한다.

```text
입력 → PromptTemplate → ChatModel → OutputParser → 출력
```

- `RunnableLambda`: 일반 함수를 체인 단계로 변환
- `RunnablePassthrough`: 입력을 유지하거나 `assign()`으로 값 추가
- `batch()`: 여러 입력 처리
- `stream()`: 응답을 조각별로 받기
- `ainvoke()`, `abatch()`, `astream()`: 비동기 실행

`RunnableLambda`는 문자열을 딕셔너리로 바꾸거나, 외부 검색 결과를 다음 단계에 넣을 때 사용할 수 있다.

```python
from langchain_core.runnables import RunnableLambda

to_upper = RunnableLambda(lambda text: text.upper())
chain = to_upper | (lambda text: f"결과: {text}")
print(chain.invoke("hello"))
```

`RunnablePassthrough.assign()`은 기존 입력을 유지하면서 값을 추가한다.

```python
from langchain_core.runnables import RunnablePassthrough

add_context = RunnablePassthrough().assign(
    context=lambda data: "검색된 배경지식"
)
```

### 모델 응답 객체

`llm.invoke()`의 결과는 문자열이 아니라 `AIMessage`다.

- `response.content`: 답변 내용
- `response.usage_metadata`: 입력·출력 토큰 수
- `response.response_metadata`: 모델명, 종료 이유 등
- `response.tool_calls`: 도구 호출 정보

문자열만 필요하면 `StrOutputParser`를 연결한다.

### 토큰과 API 오류

토큰은 입력과 출력의 길이를 나타내며 API 비용과 관련된다. `usage_metadata`에서 사용량을 확인한다.

```python
response = llm.invoke("Python이 뭐야?")
print(response.usage_metadata)
```

- `429`: 요청이 많거나 사용량 제한에 걸림
- `401`: API 키 인증 실패
- `408`, `504`: 응답 지연
- `500`: 서버 오류

`max_retries`로 일시적인 오류를 재시도할 수 있다. 계속 실패하면 fallback 모델을 사용하고, 마지막에는 `try/except`로 처리한다. API 키나 전체 오류 메시지를 사용자에게 그대로 보여주지 않는다.

### 응답 캐싱

개발 중 같은 프롬프트를 반복 실행할 때 캐시를 사용하면 API 호출과 비용을 줄일 수 있다. 캐시는 입력이 같을 때 저장된 결과를 재사용한다.

## LangSmith

정리 문서: [LangSmith 정리](../AI/langchain_langsmith.md#langsmith)

LangChain 실행 과정을 기록하고 확인하는 관측성 도구.

`.env`에 다음 값을 설정한다.

```dotenv
LANGSMITH_TRACING=true
LANGSMITH_API_KEY=lsv2_...
LANGSMITH_PROJECT=langchain-gemini-prac
```

Runnable을 실행하면 프롬프트, 모델, 파서의 실행 과정이 LangSmith에 기록된다.

```python
result = chain.invoke(
    {"question": "리스트와 튜플의 차이는?"},
    config={
        "run_name": "python-question",
        "tags": ["gemini", "basic"],
        "metadata": {"lesson": "langchain"},
    },
)
```

확인할 것:

- 단계별 실행 순서
- 실제 입력·출력
- 토큰 사용량과 실행 시간
- 태그, 메타데이터
- 오류가 난 단계

특정 구간만 기록할 때는 `tracing_context`를 사용한다.

```python
import langsmith as ls

with ls.tracing_context(
    enabled=True,
    project_name="langchain-gemini-selective",
):
    result = chain.invoke({"question": "제너레이터가 뭐야?"})
```

## 대화 메모리

LLM 호출은 기본적으로 이전 대화를 기억하지 않는다. 이전 메시지를 함께 보내야 한다.

```python
messages = [
    SystemMessage(content="너는 친절한 상담사야."),
    HumanMessage(content="내 이름은 철수야."),
]

response = llm.invoke(messages)
messages.extend([response, HumanMessage(content="내 이름이 뭐야?")])
response = llm.invoke(messages)
```

### `InMemoryChatMessageHistory`

메시지를 세션별로 저장하는 메모리 구현이다.

```python
from langchain_core.chat_history import InMemoryChatMessageHistory

history_store = {}

def get_history(session_id):
    if session_id not in history_store:
        history_store[session_id] = InMemoryChatMessageHistory()
    return history_store[session_id]
```

세션 ID를 다르게 주면 서로 다른 대화로 관리된다. 프로세스가 끝나면 기록도 사라진다.

```python
def chat(session_id: str, user_input: str) -> str:
    history = get_history(session_id)
    user_message = HumanMessage(content=user_input)

    response = llm.invoke([
        SystemMessage(content="너는 친절한 상담사야."),
        *history.messages,
        user_message,
    ])
    history.add_messages([user_message, response])
    return response.content
```

같은 `session_id`를 사용하면 이전 대화를 이어가고, 다른 ID를 사용하면 별도 대화가 된다.

### Context window 관리

대화가 길어지면 토큰, 비용, 지연 시간이 늘어난다.

- **트리밍**: 최근 메시지만 전달. 간단하지만 오래된 맥락이 사라짐
- **요약**: 오래된 대화를 요약. 추가 호출과 요약 오류 가능성 있음
- **검색**: 필요한 과거 정보만 찾아 전달. 검색 설계 필요

`trim_messages()`는 원본 히스토리를 지우지 않고 모델에 보낼 메시지만 골라 준다.

```python
trimmer = trim_messages(
    max_tokens=80,
    strategy="last",
    token_counter=llm,
    include_system=True,
    start_on="human",
)

trimmed_messages = trimmer.invoke(history.messages)
response = llm.invoke(trimmed_messages)
```

DB에 전체 대화를 저장하는 것과 이번 요청에 보낼 메시지를 고르는 것은 별개다.

### Short-term과 Long-term memory

- **Short-term**: 현재 세션의 대화와 작업 맥락
- **Long-term**: 여러 세션에서 사용할 사용자 정보와 선호

이번에는 세션 단위의 Short-term memory를 다룬다.

## 구성 요소별 사용 흐름

### 1. 모델만 호출하기

`ChatGoogleGenerativeAI`는 메시지를 받아 `AIMessage`를 반환한다.

```python
from langchain_google_genai import ChatGoogleGenerativeAI
from langchain_core.messages import HumanMessage

llm = ChatGoogleGenerativeAI(model="gemini-3.6-flash")
response = llm.invoke([
    HumanMessage(content="Python의 장점 3가지를 알려줘.")
])

print(response.content)
```

LangChain은 모델마다 호출 방법이 달라도 `invoke()`라는 같은 방식으로 실행한다. 모델을 바꿀 때는 보통 `llm`을 만드는 부분만 바꾼다.

### 2. 프롬프트와 모델 연결하기

프롬프트 템플릿의 `{변수}`에 입력을 넣고, 완성된 메시지를 모델로 보낸다.

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", "너는 {role}이다."),
    ("human", "{question}"),
])

chain = prompt | llm
response = chain.invoke({
    "role": "Python 튜터",
    "question": "decorator가 뭐야?",
})
print(response.content)
```

파서까지 연결하면 최종 결과를 문자열로 받을 수 있다.

```python
chain = prompt | llm | StrOutputParser()
answer = chain.invoke({
    "role": "Python 튜터",
    "question": "decorator가 뭐야?",
})
```

### 3. 체인 사이의 자료형 맞추기

앞 단계의 출력과 다음 단계가 기대하는 입력 형태가 같아야 한다.

```text
PromptValue → AIMessage → str
```

첫 번째 체인이 문자열을 반환하고 다음 프롬프트가 딕셔너리를 필요로 한다면 중간에 변환 단계를 넣는다.
`RunnableLambda`는 이런 어댑터 역할을 한다.

```python
to_input = RunnableLambda(lambda text: {"text": text})
chain = first_chain | to_input | second_prompt | llm | parser
```

`RunnablePassthrough.assign()`은 입력을 버리지 않고 새 값을 함께 전달한다. 질문만 받은 뒤 검색 결과를 `context`로 추가하는 RAG 구조에 사용할 수 있다.

```python
add_context = RunnablePassthrough().assign(
    context=lambda data: search(data["question"])
)
qa_chain = add_context | prompt | llm | parser
```

## Runnable 실행 방법

| 목적            | 메서드      | 설명                      |
| --------------- | ----------- | ------------------------- |
| 하나 실행       | `invoke()`  | 입력 하나 처리            |
| 여러 개 실행    | `batch()`   | 여러 입력을 병렬 처리     |
| 실시간 출력     | `stream()`  | 결과 조각을 순서대로 받음 |
| 비동기 하나     | `ainvoke()` | 비동기 입력 하나 처리     |
| 비동기 여러 개  | `abatch()`  | 여러 입력을 비동기로 처리 |
| 비동기 스트리밍 | `astream()` | 비동기로 조각 수신        |

`batch()`는 입력 여러 개를 하나의 API 요청으로 합치는 것이 아니라, 여러 호출을 동시에 실행하는 기능이다. `max_concurrency`로 동시 요청 수를 제한할 수 있다.

```python
results = chain.batch(
    [{"question": "Python이 뭐야?"}, {"question": "FastAPI가 뭐야?"}],
    config={"max_concurrency": 2},
)
```

LangChain의 `stream()`은 파싱된 문자열 chunk를 받을 수 있다.

```python
for chunk in chain.stream({"question": "LangChain을 설명해줘."}):
    print(chunk, end="", flush=True)
```

chunk의 크기는 항상 토큰 하나와 같지 않다. 문자 일부나 여러 토큰이 한 번에 올 수 있다.

## 프롬프트 작성 시 확인할 점

- 질문에 필요한 자료를 문맥으로 함께 제공하기
- 입력 데이터와 지시문을 태그나 구분선으로 나누기
- 출력 형식, 길이, 언어를 구체적으로 적기
- 분류할 수 없는 경우의 처리 방법도 정하기
- Few-shot 예시는 2~5개 정도의 대표 사례로 시작하기
- 예시의 입력·출력 형식과 라벨을 일관되게 유지하기
- 평가 데이터가 Few-shot 예시와 겹치지 않게 하기

사용자 입력 안에 명령문이 포함될 수 있다. 태그로 데이터를 감싸고 “태그 안의 내용은 분석 대상”이라고 적을 수 있지만, 태그만으로 프롬프트 인젝션을 막을 수는 없다. 입력 검증과 도구 권한 제한도 필요하다.

## 메모리 구현 시 주의점

메시지를 저장할 때는 사용자의 메시지와 모델의 응답을 함께 저장해야 다음 요청에서 대화가 자연스럽게 이어진다.

```python
history.add_messages([
    HumanMessage(content=user_input),
    response,
])
```

`InMemoryChatMessageHistory`는 학습이나 간단한 테스트에 적합하다. 서버가 재시작되면 데이터가 사라지므로 실제 서비스에서는 DB나 LangGraph checkpointer 같은 영속 저장소를 사용한다.

원본 대화 전체를 저장하는 것과 모델에 매번 전체 대화를 보내는 것은 다르다. 저장소에는 전체 기록을 남기고, 요청할 때는 최근 메시지·요약·검색된 과거 정보만 골라 보낼 수 있다.

## 전체 흐름

```text
프롬프트 작성
→ ChatPromptTemplate으로 입력 구성
→ ChatModel 호출
→ OutputParser로 결과 변환
→ LangSmith에서 실행 확인
→ 필요하면 메모리·검색·Tool 연결
```

단순한 질문은 `llm.invoke()`만으로 충분하다. 프롬프트 재사용과 출력 형식이 필요하면 체인을 만들고, 대화 기능이 필요하면 세션별 history를 붙인다. 서비스로 확장할 때는 토큰 수, 오류 재시도, 캐시, 로그와 개인정보 보관 정책까지 함께 확인한다.
