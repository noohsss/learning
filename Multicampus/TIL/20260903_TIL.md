## 벡터 DB

정리 문서: [RAG 기초 - 벡터 DB](../AI/rag_basic.md#vector-db)

벡터 DB는 임베딩 벡터와 원본 텍스트, metadata를 저장하고 유사도 검색을 수행한다.
일반 DB가 정확한 값 검색에 강하다면, 벡터 DB는 의미가 비슷한 문서를 찾는 데 사용한다.

```text
문서 → 청크 분할 → 임베딩 → 벡터·원문·metadata 저장
질문 → 질문 임베딩 → 유사 벡터 검색 → 관련 문서 반환
```

### Chroma

`Chroma.from_documents()`로 문서를 저장하고, `persist_directory`를 지정하면 로컬에 보존할 수 있다.
저장한 벡터 DB는 같은 임베딩 모델을 사용해 다시 연결한다.

```python
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    collection_name="company_rules",
    persist_directory="./chroma_db",
)
```

metadata에는 출처, 페이지, 문서 분류, 사용자 ID 등을 저장한다. 의미 검색에는 사용하지 않고 필터링과 출처 확인에 사용한다.

## RAG 파이프라인

정리 문서: [RAG 기초 - RAG Chain](../AI/rag_basic.md#rag-chain)

인덱싱 단계에서 문서를 미리 저장하고, 질문이 들어오면 Retriever로 관련 문서를 가져와 `context`에 넣는다.

```python
retriever = vectorstore.as_retriever(
    search_kwargs={"k": 4}
)

def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)

rag_chain = (
    {
        "context": retriever | format_docs,
        "question": RunnablePassthrough(),
    }
    | prompt
    | llm
    | StrOutputParser()
)
```

`Document`의 metadata를 함께 출력하면 답변의 출처와 페이지를 확인할 수 있다.

## 고급 검색

정리 문서: [RAG 기초 - 고급 검색 전략](../AI/rag_basic.md#고급-검색-전략)

- **MMR**: 관련성과 결과 간 다양성을 함께 고려. 비슷한 결과가 반복될 때 사용
- **BM25**: 단어가 실제로 일치하는지 검색. 모델명, 코드, 약어에 유리
- **Metadata Filter**: 날짜·권한·분류처럼 반드시 지켜야 할 조건을 검색 범위에 적용
- **Hybrid Search**: 벡터 검색과 BM25를 결합
- **Re-ranking**: 검색된 후보를 다시 평가해 순서를 변경

```python
mmr_docs = vectorstore.max_marginal_relevance_search(
    question, k=6, fetch_k=20, lambda_mult=0.5
)
```

`k`는 최종 결과 수, `fetch_k`는 MMR이 검토할 후보 수다. `lambda_mult`가 1에 가까우면 관련성, 0에 가까우면 다양성을 더 중시한다.

검색 전략은 문제에 맞게 선택한다. 처음 검색에서 문서를 놓쳤다면 Re-ranking으로 복구할 수 없으므로 문서 로딩, 청킹, 임베딩, 검색 결과를 먼저 확인한다.
