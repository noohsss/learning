## Subgraph 실습

### 실습: 학습 콘텐츠 생성 그래프

학습 주제를 입력하면 설명을 생성하고, 생성된 설명을 바탕으로 확인 문제를 만드는 구조다. 설명 생성과 퀴즈 생성을 각각 별도의 Subgraph로 만들고, 부모 그래프에서 두 Subgraph를 순서대로 연결한다.

- `LearningState`: 부모 그래프와 설명 Subgraph가 공유하는 State
- `QuizState`: 퀴즈 Subgraph가 사용하는 별도의 State
- `explanation_graph`: 학습 주제를 설명으로 변환
- `quiz_graph`: 설명 내용을 퀴즈로 변환
- `quiz_wrapper`: 부모 State의 `explanation`을 퀴즈 Subgraph의 `source_text`로 변환
- `subgraphs=True`: 부모 그래프와 내부 Subgraph의 실행 이벤트를 함께 확인

설명 Subgraph는 부모와 같은 `LearningState`를 사용하므로 컴파일된 그래프를 부모 노드로 직접 등록한다. 퀴즈 Subgraph는 State 구조가 다르기 때문에 래퍼 함수에서 부모의 `explanation`을 `source_text`로 전달하고, 반환된 `questions`를 부모의 `quiz`에 저장한다.

```python
class LearningState(TypedDict):
    topic: str
    explanation: str
    quiz: str


def explanation_node(state: LearningState):
    system = SystemMessage(
        content="너는 개념 설명 전문가다. 학습 주제를 초보자도 이해할 수 있게 설명해."
    )
    response = llm.invoke([system, HumanMessage(content=state["topic"])])
    return {"explanation": response.text}


# TODO: LearningState를 사용하는 설명 Subgraph를 만들고 컴파일한다.

builder = StateGraph(LearningState)
builder.add_node('explanation_node', explanation_node)

builder.add_edge(START, 'explanation_node')
builder.add_edge('explanation_node', END)

explanation_graph = builder.compile()

result = explanation_graph.invoke({'topic' : '랭그래프의 서브그래프'})
print(result['explanation'])
```

위 코드는 `LearningState`를 사용하는 설명 Subgraph다. `explanation_node`는 입력으로 받은 `topic`을 LLM에 전달하고, 응답을 `explanation` 필드에 저장한다.

```python
class QuizState(TypedDict):
    source_text: str
    questions: str


def quiz_node(state: QuizState):
    system = SystemMessage(

    )
    response = llm.invoke([system, HumanMessage(content=state["source_text"])])
    return {"questions": response.text}

builder.add_edge(START, 'quiz_node')
builder.add_edge('quiz_node', END)

result = quiz_graph.invoke({'source_text' : "파이썬은 프로그래밍 언어다. 쉽고 빠르다. ai agent를 만드는데 사용된다."})

print(result)
print(result['questions'])
# TODO: 래퍼 함수에서 explanation을 source_text로 전달하여 퀴즈 Subgraph를 호출하고,
#       반환된 questions를 부모 State의 quiz에 저장한다.

# 부모의 노드.
def quiz_wrapper(state: LearningState):
    explanation = state['explanation']
    result = quiz_graph.invoke({'source_text': explanation})

    return {
        'quiz' : result['questions']
    }
```

퀴즈 Subgraph는 `QuizState`를 사용한다. 부모 State와 필드 이름이 다르기 때문에 `quiz_wrapper`가 두 그래프 사이의 변환 역할을 한다. 이 함수는 설명 결과를 퀴즈 입력으로 전달하고, 퀴즈 결과를 부모 State의 `quiz`로 반환한다.

```python
# TODO: 설명 Subgraph와 퀴즈 래퍼를 부모 그래프의 노드로 등록한다.
builder = StateGraph(LearningState)
builder.add_node('explanation', explanation_graph) # node가 graph 그 자체
builder.add_node('quiz', quiz_wrapper) # node가 graph를 wrapping한 함수.

builder.add_edge(START, 'explanation')
builder.add_edge('explanation', 'quiz')
builder.add_edge('quiz', END)

parent_graph = builder.compile()

# TODO: START → 설명 → 퀴즈 → END 순서로 연결하고 컴파일한다.


# TODO: 완성한 그래프를 subgraphs=True, stream_mode="updates"로 실행한다.
# 입력: {"topic": "LangGraph의 State와 Reducer"}
# 각 이벤트의 namespace, 노드 이름, State 변경분을 출력한다.

for namespace, chunk in parent_graph.stream(
    {'topic' : 'LangGraph의 State와 Reducer'},
    subgraphs=True,
    stream_mode="updates",
):
    for node_name, state in chunk.items():
        print("=" * 60)
        print(f"Graph: {namespace}")
```

부모 그래프는 `설명 Subgraph → 퀴즈 래퍼 → END` 순서로 실행된다. `subgraphs=True`와 `stream_mode="updates"`를 함께 사용하면 부모 그래프의 이벤트뿐 아니라 내부 Subgraph에서 발생한 이벤트도 `namespace`와 함께 출력할 수 있다.

## Handoff 실습

### 실습: 문서 검토 상태 전환

문서 승인 여부에 따라 다음 Node와 State를 동시에 결정하는 그래프다. `Command`의 `update`로 상태를 변경하고, `goto`로 다음 Node를 선택한다.

- 승인된 문서: `status`를 `approved`로 변경한 뒤 `publish_document`로 이동
- 승인되지 않은 문서: `status`를 `revision_required`로 변경한 뒤 `revise_document`로 이동
- 각 처리 Node는 `result`를 저장하고 그래프를 종료

```python
class ReviewState(TypedDict):
    document: str
    approved: bool
    status: str
    result: str


def publish_document(state: ReviewState) -> dict:
    return {"result": "문서를 게시했습니다."}


def revise_document(state: ReviewState) -> dict:
    return {"result": "문서를 수정 단계로 보냈습니다."}


# TODO: approved에 따라 status를 변경하고 다음 Node를 선택하는 Node를 정의한다.

def node(state: ReviewState) -> Command[Literal['publish_document', 'revise_document']]:
    if state["approved"]:
        return Command(
            goto='publish_document',
            update={'status': 'approved'}
        )
    return Command(
        goto='revise_document',
        update={'status': 'revision_required'}
    )
# TODO: Command의 update와 goto를 사용해 StateGraph를 구성하고 실행한다.

builder = StateGraph(ReviewState)
builder.add_node('publish_document', publish_document)
builder.add_node('revise_document', revise_document)
builder.add_node('node', node)

builder.add_edge(START, 'node')
builder.add_edge('publish_document', END)
builder.add_edge('revise_document', END)

graph = builder.compile()

display(Image(graph.get_graph().draw_mermaid_png()))
```

이 구조에서는 일반적인 Conditional Edge를 별도로 만들지 않고, `node`가 `Command`를 반환하면서 상태 변경과 이동을 함께 처리한다. `Literal`은 `goto`로 이동할 수 있는 Node를 타입으로 명시한다.

### handoff 실습 시나리오

제품 판매 상담과 기술 지원 상담을 서로 다른 Agent가 담당한다. 사용자는 Sales Agent와 대화를 시작하며, 문의 내용에 따라 Support Agent로 제어권이 넘어간다.

- Sales Agent: 제품, 가격, 구매 방법 문의
- Support Agent: 설치, 오류, 고장 등 기술 문의
- Handoff 이후에는 전환된 Agent가 같은 Thread의 후속 대화를 담당

### Handoff를 수행하는 Tool

Handoff Tool은 일반적인 결과를 반환하는 대신 `Command`를 반환한다. `graph=Command.PARENT`를 지정해 현재 Agent의 내부 Graph에서 부모 Graph로 이동하고, 부모 State의 `active_agent`와 `messages`를 갱신한다.

```python
def find_last_ai_message(messages: list) -> AIMessage:
    for message in reversed(messages):
        if isinstance(message, AIMessage):
            return message
    raise ValueError("AIMessage를 찾을 수 없습니다.")


@tool
def transfer_to_sales(runtime: ToolRuntime) -> Command:
    """제품, 가격, 구매 문의를 Sales Agent에게 넘긴다."""
    last_ai_message = find_last_ai_message(runtime.state["messages"])
    transfer_message = ToolMessage(
        content="Sales Agent로 전환했습니다.",
        tool_call_id=runtime.tool_call_id,
    )
    return Command(
        goto="sales_agent",
        update={
            "active_agent": "sales_agent",
            "messages": [last_ai_message, transfer_message],
        },
        graph=Command.PARENT,
    )


@tool
def transfer_to_support(runtime: ToolRuntime) -> Command:
    """설치, 오류, 고장 등 기술 문의를 Support Agent에게 넘긴다."""
    last_ai_message = find_last_ai_message(runtime.state["messages"])
    transfer_message = ToolMessage(
        content="Support Agent로 전환했습니다.",
        tool_call_id=runtime.tool_call_id,
    )
    return Command(
        goto="support_agent",
        update={
            "active_agent": "support_agent",
            "messages": [last_ai_message, transfer_message],
        },
        graph=Command.PARENT,
    )
```

Handoff Tool은 현재 Agent의 마지막 `AIMessage`와 Tool 실행 결과인 `ToolMessage`를 부모 Graph에 함께 전달한다. `tool_call_id`를 동일하게 연결하면 모델의 Tool 호출과 실행 결과의 관계를 유지할 수 있다.

```python
sales_agent = create_agent(
    model=llm,
    tools=[transfer_to_support],
    system_prompt=(
        "너는 제품 판매 상담을 담당하는 Sales Agent다. "
        "대화 기록에서 최신 사용자 요청의 주된 의도를 확인해. "
        "제품 정보, 가격, 구매 방법에 관한 문의라면 사용자에게 직접 답해. "
        "설치, 오류, 고장 등 기술 지원이 필요한 문의라면 직접 답하지 말고 "
        "transfer_to_support만 호출해. Handoff Tool은 한 번에 하나만 호출해."
    ),
    name="sales_agent",
)

support_agent = create_agent(
    model=llm,
    tools=[transfer_to_sales],
    system_prompt=(
        "너는 기술 지원을 담당하는 Support Agent다. "
        "대화 기록에서 최신 사용자 요청의 주된 의도를 확인해. "
        "설치, 오류, 고장 등 기술 문의라면 사용자에게 직접 답해. "
        "제품 정보, 가격, 구매 방법에 관한 문의라면 직접 답하지 말고 "
        "transfer_to_sales만 호출해. Handoff Tool은 한 번에 하나만 호출해."
    ),
    name="support_agent",
)
```

각 Agent에는 자신의 담당 범위를 벗어났을 때 호출할 Handoff Tool만 제공한다. 담당 범위에 맞는 요청이면 직접 답하고, 다른 Agent의 영역이면 해당 Agent로 전환한다.

```python
class MultiAgentState(MessagesState):
    active_agent: str


def route_to_active_agent(
    state: MultiAgentState,
) -> Literal["sales_agent", "support_agent"]:
    return state["active_agent"]


def route_after_agent(
    state: MultiAgentState,
) -> Literal["sales_agent", "support_agent", "__end__"]:
    last_message = state["messages"][-1]
    if isinstance(last_message, AIMessage) and not last_message.tool_calls:
        return "__end__"
    return state["active_agent"]


handoff_builder = StateGraph(MultiAgentState)
handoff_builder.add_node("sales_agent", sales_agent)
handoff_builder.add_node("support_agent", support_agent)

handoff_builder.add_conditional_edges(
    START,
    route_to_active_agent,
    ["sales_agent", "support_agent"],
)
handoff_builder.add_conditional_edges(
    "sales_agent",
    route_after_agent,
    ["sales_agent", "support_agent", END],
)
handoff_builder.add_conditional_edges(
    "support_agent",
    route_after_agent,
    ["sales_agent", "support_agent", END],
)

handoff_graph = handoff_builder.compile(checkpointer=InMemorySaver())
```

부모 Graph는 `active_agent`를 기준으로 첫 실행 Agent를 선택한다. Agent가 일반 응답을 반환하면 종료하고, Handoff Tool을 호출하면 갱신된 `active_agent`를 기준으로 다른 Agent Node를 실행한다. Checkpointer와 같은 `thread_id`를 사용하면 Agent 전환 상태가 다음 대화까지 유지된다.

```python
display(Image(handoff_graph.get_graph().draw_mermaid_png()))
```

### 실행

처음에는 Sales Agent에게 제품 가격과 구매 방법을 질문한다. 이후 같은 `config`를 사용해 기술 문의를 보내면 Support Agent로 전환되고, 후속 기술 질문은 Support Agent가 계속 처리한다. 다시 제품과 가격을 질문하면 Sales Agent로 돌아간다.

```python
config = {"configurable": {"thread_id": "customer-2"}}

first_state = handoff_graph.invoke(
    {
        "messages": [HumanMessage(content="AI 스피커 가격과 구매 방법을 알려줘.")],
        "active_agent": "sales_agent",
    },
    config=config,
)

print("Active agent:", first_state["active_agent"])
print("Final response:", first_state["messages"][-1].text)
```

```python
for namespace, update in handoff_graph.stream(
    {"messages": [HumanMessage(content="구매한 제품이 Wi-Fi에 연결되지 않아.")]},
    config=config,
    stream_mode="updates",
    subgraphs=True,
):
    graph_name = namespace[-1].split(":")[0] if namespace else "parent"
    node_name = next(iter(update))
    node_update = update[node_name]
    print(f"\n{graph_name} -> {node_name}")

    if isinstance(node_update, dict):
        messages = node_update.get("messages", [])
        if messages:
            message = messages[-1]
            if getattr(message, "tool_calls", None):
                tool_names = [call["name"] for call in message.tool_calls]
                print("Tool calls:", tool_names)
            if message.text:
                print(message.text)

second_state = handoff_graph.get_state(config).values
print("\nActive agent:", second_state["active_agent"])
print("Final response:", second_state["messages"][-1].text)
```

첫 번째 기술 문의에서는 스트리밍 로그의 Agent 이름과 Tool 호출을 확인하고, 실행 후 `active_agent`가 `support_agent`로 바뀌었는지 확인한다.
