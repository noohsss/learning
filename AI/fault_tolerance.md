# Fault Tolerance

Fault Tolerance는 외부 서비스 오류, 노드 실패, 응답 지연 같은 장애가 발생해도 작업을 재시도하거나 저장된 상태에서 재개해 전체 시스템이 안정적으로 동작하도록 하는 설계다.

## 자동 재시도

`RetryPolicy`는 지정한 Node에서 특정 예외가 발생했을 때 같은 Node를 자동으로 다시 실행한다. 이미 완료된 이전 Node는 다시 실행하지 않는다.

- `initial_interval`: 첫 재시도 전 대기 시간
- `backoff_factor`: 재시도마다 대기 시간을 늘리는 배수
- `max_interval`: 최대 대기 시간
- `max_attempts`: 최초 실행을 포함한 최대 시도 횟수
- `jitter`: 재시도 간격에 무작위 변동을 추가할지 여부
- `retry_on`: 재시도할 예외 타입 또는 판별 함수

재시도는 일시적인 네트워크 오류처럼 다시 실행하면 성공할 가능성이 있는 가장 작은 단위에 적용해야 한다. 잘못된 입력처럼 반복해도 해결되지 않는 오류는 재시도 대상에서 제외하는 편이 좋다.

## 오류 유형 구분

- 일시적 오류: 네트워크 단절, 외부 서비스의 순간적인 장애
- 영구적 오류: 잘못된 요청 형식, 권한 부족, 존재하지 않는 리소스
- 제한 시간 초과: 응답이 정해진 시간 안에 도착하지 않은 경우

오류 유형을 구분하지 않으면 불필요한 재시도로 비용과 지연이 증가한다. 예외 타입, 상태 코드, 오류 내용을 기준으로 재시도 정책을 세분화할 수 있다.

## Checkpoint 재개

자동 재시도로도 실패하면 Checkpointer에 저장된 State와 `next` 정보를 바탕으로 실행을 나중에 재개할 수 있다.

```python
graph.invoke(None, config)
```

`None`은 새로운 입력 없이 저장된 실행을 이어간다는 의미다. 완료된 Node의 결과는 재사용하고 실패한 Node부터 다시 실행하므로, 전체 그래프를 처음부터 반복하지 않는다.

## 병렬 실행의 장애 처리

같은 super-step에 여러 Node가 실행될 때 일부 Node만 실패할 수 있다. 이때 성공한 Node의 결과는 보존하고, 재개 시 실패한 Node만 다시 실행하는 방식으로 이미 완료된 작업의 중복 실행을 줄일 수 있다.

## Timeout과 재시도

비동기 Node의 실행 시간이 길어지는 경우 `TimeoutPolicy`로 한 번의 실행 시간을 제한할 수 있다. `NodeTimeoutError`를 `RetryPolicy`의 재시도 대상으로 지정하면 새 시도마다 시간 제한이 다시 적용된다.

## Error Handler

재시도 횟수를 모두 소진했을 때 `error_handler`를 통해 실패 상태를 기록하고 별도의 종료 Node로 이동할 수 있다. 오류를 State에 저장하면 사용자 안내, 운영 모니터링, 후속 복구 작업에 활용할 수 있다.

## 설계 기준

- 재시도 가능한 예외와 즉시 실패해야 하는 예외를 구분한다.
- 외부 작업은 중복 실행을 고려해 멱등성을 확보한다.
- 짧은 오류에는 자동 재시도, 장기 장애에는 checkpoint 재개를 사용한다.
- 재시도 횟수와 대기 시간을 제한한다.
- 실패 상태와 원인을 State 또는 로그에 남긴다.
- 사용자 재시도와 백그라운드 자동 재개의 동시 실행을 방지한다.
