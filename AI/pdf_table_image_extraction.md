# PDF 표·이미지 추출과 RAG

PDF는 화면에 표시할 글자·선·도형·이미지의 위치와 모양을 저장하는 형식이다. 화면에서는 표와 문단으로 보이더라도 내부에 행·열·셀 관계가 명시되어 있지 않을 수 있다. 따라서 PDF를 RAG에 사용하려면 본문, 표, 이미지의 특성에 맞춰 추출·정리·청킹해야 한다.

## PDF 텍스트와 표의 차이

일반 텍스트 추출은 페이지에 배치된 글자를 읽을 수 있지만, 표의 열 이름과 값의 관계나 병합 셀 구조를 보존하지 못할 수 있다. 표는 선·도형·글자 좌표를 이용해 행과 열을 재구성해야 한다.

스캔 PDF처럼 텍스트 정보가 없는 문서는 OCR이나 비전 모델이 필요하다. 표의 테두리가 없거나 병합 셀이 많은 경우에도 좌표와 내용 정리가 추가로 필요하다.

## 표 추출 과정

```text
표 후보 탐색 → 대상 표 선택 → 영역 확인 → 셀 추출 → 병합 셀 정리 → Markdown 변환
```

`pdfplumber`는 PDF에 저장된 가로·세로선과 글자 위치를 이용해 표의 경계와 셀을 추정한다. 선이 만나는 지점으로 셀을 구성하고 셀 안의 글자를 행·열 순서로 정리한다.

표를 Markdown으로 변환할 때는 다음을 확인해야 한다.

- 열 이름과 데이터 행의 대응 관계
- 병합 셀로 인해 비어 있는 값의 의미
- 셀 안의 줄바꿈과 불필요한 공백
- 표 아래 각주와 단위
- 원본 페이지와 표 영역 좌표

## 이미지 내용 추출

PDF의 이미지는 로고·장식뿐 아니라 표, 그래프, 설명 문장을 포함할 수 있다. 모든 이미지를 처리하면 불필요한 비용이 커지므로 페이지 면적, 이미지 크기, 내용 유형을 기준으로 읽을 대상을 선택한다.

이미지 추출 흐름은 다음과 같다.

```text
이미지 후보 탐색 → 크기·영역 기준 선택 → 이미지 확인 → 비전 모델 또는 OCR 처리 → 원문 위치 연결
```

이미지 해석 결과에는 본문, 표, 숫자, 각주를 가능한 한 보존하고 읽을 수 없는 부분은 명시적으로 구분한다. 이미지 결과도 페이지 번호와 영역 좌표를 함께 저장하면 원문 검증이 가능하다.

## 내용 유형별 청킹

본문·표·이미지 해석 결과를 모두 동일한 길이 기준으로 자르면 표의 헤더와 데이터 행이 서로 다른 청크로 분리될 수 있다. 이 경우 검색된 청크만으로 열과 값의 관계를 이해하기 어렵다.

```text
본문 텍스트       → 일반 길이 기반 청킹
이미지 해석 텍스트 → 일반 길이 기반 청킹
표                → 통째로 유지 또는 행 단위 청킹
```

표를 짧은 청크로 나눠야 한다면 각 청크에 헤더와 각주를 반복하고, 데이터 행 중간은 자르지 않는다. 헤더·각주·한 행만으로도 기준 길이를 넘으면 구조 보존을 위해 길이 초과를 허용할 수 있다.

## 원문 순서와 중복 제거

표와 이미지 영역에서 이미 읽힌 글자를 페이지 본문에서 제거하고, 원래 위치에 정리된 표와 이미지 해석 결과를 배치하면 중복을 줄이면서 문서 순서를 유지할 수 있다.

```text
페이지 본문 → 본문 → 표 → 본문 → 이미지 해석 결과
```

각 결과에는 유형과 고유 ID를 저장해 여러 표·이미지를 서로 구분한다. 출처 정보는 청크의 메타데이터에 보존한다.

## RAG 연결

```text
PDF 추출 → 표·이미지 정리 → 유형별 청킹 → 임베딩 → 벡터 저장소 → 검색
```

검색 결과에는 페이지와 영역 같은 출처를 함께 반환해야 답변의 근거를 확인할 수 있다. 표의 원본 구조를 보존한 청크를 답변 문맥으로 전달하면 제품명·수치·단위의 관계가 유지된다.

## 확장 방법

- **Contextual Retrieval**: 문서 전체와 청크를 바탕으로 청크의 배경 설명을 생성해 임베딩에 포함
- **표 요약 기반 검색**: 표 요약을 검색하고 연결된 원본 표를 답변 근거로 사용
- **PyMuPDF**: PDF 본문·이미지 추출 대안
- **Camelot**: 표 구조 추출 대안
- **Tesseract·PaddleOCR**: 이미지 속 문자 추출 대안

## 설계 기준

- PDF 유형이 디지털 텍스트인지 스캔 이미지인지 먼저 구분한다.
- 표는 헤더·행·각주·단위를 함께 보존한다.
- 이미지 해석 결과에 페이지와 영역 정보를 연결한다.
- 본문·표·이미지에 서로 다른 청킹 정책을 적용한다.
- 임베딩 입력과 메타데이터의 역할을 구분한다.
- 추출 결과를 원본과 비교할 수 있는 검증 단계를 둔다.
