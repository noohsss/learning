# Agent Tool 실행 검증과 통제

Agent는 사용자 요청을 바탕으로 실행할 Tool과 인자를 제안하지만, 실제 Tool 실행을 허용할지는 프로그램이 결정해야 한다. Tool 실행 전후에 검증 계층을 두면 잘못된 인자, 권한 없는 접근, 승인되지 않은 작업, 잘못된 반환값을 통제할 수 있다.

## Middleware

Middleware는 Agent 실행 과정의 특정 시점에 공통 처리를 끼워 넣는 구조다.

```text
Agent 시작 → 모델 호출 전 검사 → 모델 호출 → Tool 호출 전 검사 → Tool 실행 → Tool 결과 검사
```

`@wrap_tool_call`은 Tool 호출을 감싼다. `request.tool_call`에서 Tool 이름과 인자를 확인하고, `request.runtime.context`에서 프로그램이 전달한 실행 Context를 확인한다. `handler(request)`를 호출하면 다음 Middleware 또는 실제 Tool 실행으로 이어진다.

## 실행 전 검증

실행 전 검증은 실제 부작용이 발생하기 전에 요청을 차단할 수 있다.

- Tool 이름이 등록된 대상인지 확인
- 인자의 타입과 값의 범위 확인
- 접근 가능한 계좌나 리소스인지 확인
- 사용자 권한과 승인 상태 확인
- 송금 금액이나 호출 횟수 같은 업무 제한 확인

검사를 통과하면 다음 처리로 넘기고, 거절하면 `ToolMessage`에 오류 코드와 사유를 담아 모델에 전달할 수 있다. `handler`를 호출하지 않으므로 실제 Tool은 실행되지 않는다.

## 실행 Context

State는 Agent가 대화를 진행하며 갱신하는 정보이고, Context는 프로그램이 실행 기준으로 전달하는 정보다. LLM이 접근할 계좌를 제안하더라도 실제 권한은 Context를 기준으로 판단해야 한다.

## 실행 후 결과 검증

외부 API나 Tool이 반환하는 값은 항상 예상한 형식과 일치한다고 보장할 수 없다. `handler(request)`로 Tool을 실행한 뒤 반환된 `ToolMessage`를 검사해 필수 필드, 타입, 요청 리소스와의 일치 여부를 확인할 수 있다.

잘못된 결과는 모델에 그대로 전달하지 않고 오류 메시지로 변환한다. 다만 실행 후 검증은 이미 수행된 외부 작업을 되돌리지 못하므로 부작용이 있는 Tool은 실행 전 검증이 더 중요하다.

## 호출 횟수 제한

`ToolCallLimitMiddleware`는 한 번의 Agent 실행에서 Tool이 호출될 수 있는 횟수를 제한한다. 전체 Tool에 공통 한도를 적용하거나 특정 `tool_name`에만 한도를 적용할 수 있다. 무한 반복 호출과 예상하지 못한 비용 증가를 방지하는 안전장치다.

## 모델 호출 제어

모델 Middleware에서는 `request.override(tool_choice=...)`처럼 호출 설정을 변경할 수 있다. 첫 호출에 Tool 사용을 강제하고, Tool 결과 이후에는 추가 Tool 호출을 막는 식으로 실행 단계를 제어할 수 있다.

## 설계 기준

- LLM의 제안과 프로그램의 실행 권한을 분리한다.
- 실행 전 검증과 실행 후 검증의 책임을 구분한다.
- 오류는 일관된 코드와 메시지 구조로 반환한다.
- 민감한 작업은 권한과 승인 검사를 통과해야 실행한다.
- Tool 호출 횟수와 재귀적 호출을 제한한다.
- 외부 작업이 이미 완료된 뒤 결과 검증이 실패할 수 있음을 고려한다.
